# Token parity drift: web vs NuvioMobile source (research for #45, map #44)

Question: where do web tokens (`css/base.css`, `css/phone.css` motion/color/type/spacing/radius)
drift from NuvioMobile's `Tokens.kt`, `ThemeColors.kt`, `TypeScale.kt`, `ThemeAccent.kt`,
`PosterCardDimensions.kt`?

Method: primary sources only, no implementation. Read the five source files plus the two
adjacent files that change their meaning (`Theme.kt` overrides the type scale and default
theme; `AppTheme.kt` owns theme ordering), and diffed against `css/base.css` (token
definitions) and `css/phone.css` (token consumption + hardcoded values).

Source pins (both verified 2026-09-09):

- NuvioMobile `/tmp/NuvioMobile` @ `a30bf51` (2026-09-07) — equals
  `git ls-remote https://github.com/NuvioMedia/NuvioMobile HEAD`, no re-clone needed.
  Files under `composeApp/src/commonMain/kotlin/com/nuvio/app/core/ui/`.
- Web: this repo @ `a6a7491` (branch `research/parity-tokens`).

How to read the table: each row is one drift. "Web value" is what the phone UI actually
renders today (token or hardcoded literal with file:line). "Source value" is the NuvioMobile
value with file:line. "Surfaces" names what a fix would touch. Rows marked `value-match,
token-miss` render correctly today but bypass the token (no single place to update);
rows marked `VALUE DRIFT` render differently from source.

## C. Type (live scale is `Theme.kt`, not `TypeScale.kt`)

Source subtlety: `Theme.kt` overrides `LocalNuvioTypeScale` with `NuvioTypeTokens`
(`Theme.kt:129+`), so the **live** weights are SemiBold titles / Normal bodyLg / Bold
displays — `TypeScale.kt`'s Medium-titles/Bold/ExtraBold defaults are dead at runtime.
Font is JetBrains Sans, 3 cuts only (Bold/SemiBold/Regular, `Theme.kt:~60-67`).

| Token                             | Web value                                                                           | Source value                                                                                         | Surfaces affected                                                                               |

## E. Motion

Durations and curves are all **defined** correctly (`base.css:242-254` matches
`Tokens.kt:102-115` incl. the identical standard/emphasized curve). The drift is in
**consumption**:

| Token                                                                                                                    | Web value                              | Source value                                    | Surfaces affected                                                            |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------- |
| `sheetExit` 250ms                                                                                                        | Defined, **never used** in `phone.css` | `Tokens.kt:107`                                 | Sheet dismiss runs at enter/normal speed                                     |
| `cinematic` 700ms                                                                                                        | Defined, **never used**                | `Tokens.kt:109`                                 | Hero/zoom transitions run at slow-400/normal instead of cinematic            |
| `instant` 0ms                                                                                                            | Defined, never used                    | `Tokens.kt:103`                                 | Minor                                                                        |
| `decelerate` / `accelerate` curves                                                                                       | Defined, **never used**                | `Tokens.kt:113-114`                             | All motion runs on standard/emphasized; exits that should accelerate don't   |
| Hardcoded `transition: background 0.15s ease` (switch `phone.css:3690`), `transform 0.15s ease` (thumb `phone.css:3706`) | `ease` ≠ `cubic-bezier(0.2,0,0,1)`     | `--phone-motion-fast` + `--phone-ease-standard` | VALUE DRIFT (subtle): toggle feels different from every token-driven control |

## Suggested fidelity order (for #48 grilling, notprescriptive)

1. Flip active alias Crimson→White (one-line + card `#241A1A`→`#222222` audit) — biggest visible delta.
2. Title/bodyLg weights 700/600→600/400 — second-biggest visible delta, touches every screen.
3. Port missing 5 palettes + per-theme `focusBackground`/`onSecondary` + accent gradients (or explicitly scope them out).
4. Tokenize overlay/border/disabled alphas; fix switch-track 0.16 and badge 0.14.
5. Sheet-exit/cinematic/decelerate/accelerate consumption; shimmer 1.6s→2.4s.
6. Decide scope for Z-scale, max-widths, AMOLED, 3/4 aspect, tab-bar chrome (custom vs source-haze).
